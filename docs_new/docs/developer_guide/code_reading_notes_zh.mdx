## 1. 先建立心智模型

SGLang 由两层组成：

| 层 | 目录 | 职责 |
|---|---|---|
| **SRT（SGLang Runtime）** | `python/sglang/srt/` | 本地模型 serving：调度、KV cache、并行、OpenAI API |
| **Frontend Language** | `python/sglang/lang/` | 可编程生成 DSL（多后端），不是 HTTP serving 主路径 |

日常部署与开发 **90% 时间在 SRT**。一条请求的最短路径：

```text
Client
  → FastAPI / OpenAI handler          # 主进程
  → TokenizerManager.generate_request
  → ZMQ (io_struct 消息)
  → Scheduler.event_loop_*            # GPU 子进程
  → TpModelWorker.forward_batch_generation
  → ModelRunner.forward
  → model.forward + RadixAttention
  → ZMQ → DetokenizerManager
  → ZMQ → TokenizerManager → HTTP 流式响应
```

记住三句话：

1. **主进程负责 tokenize / HTTP**，**每个 GPU rank 一个 Scheduler 子进程做 forward**，**另有 detokenizer 子进程**。
2. 进程间用 **ZMQ + `managers/io_struct.py` 消息** 通信，不是共享内存直接传 Python 对象（权重/KV 另论）。
3. **RadixAttention / RadixCache** 是前缀缓存与 paged KV 的核心抽象；模型文件里用 `RadixAttention` 替代普通 Attention。

## 3. 部署：从安装到可服务

### 3.1 安装选型

| 场景 | 做法 |
|---|---|
| 生产 / 快速试用 | `uv pip install --prerelease=allow sglang` 或 Docker `lmsysorg/sglang:latest` |
| **二次开发** | 源码：`pip install -e "python"`；推荐镜像 `lmsysorg/sglang:dev` |
| 可复现部署 | **钉死版本 tag**（如 `lmsysorg/sglang:v0.5.16`），不要钉 `latest`/`dev` |

细节见 [Installation](/docs/get-started/install)、[Docker 开发](/docs/developer_guide/development_guide_using_docker)。

源码开发最小步骤：

```bash
git clone https://github.com/<you>/sglang.git
cd sglang
pip install --upgrade pip
pip install -e "python"
pip install pre-commit && pre-commit install
```

### 3.2 启动入口

推荐：

```bash
sglang serve --model-path Qwen/Qwen2.5-0.5B-Instruct --host 0.0.0.0 --port 30000
```

兼容：

```bash
python3 -m sglang.launch_server --model-path meta-llama/Llama-3.1-8B-Instruct --tp 8
```

`launch_server.py` 的分支逻辑（读代码时跟这条线）：

| 条件 | 去向 |
|---|---|
| `--encoder-only` | Encode server（多模态 PD） |
| `--smg-grpc-mode` | Legacy SMG gRPC |
| `--use-ray` | Ray HTTP |
| 默认 | `entrypoints/http_server.launch_server` |

CLI 实现：`python/sglang/cli/serve.py` → 最终仍落到同一套 `ServerArgs` + `launch_server`。

### 3.3 必会 ServerArgs

定义文件：`python/sglang/srt/server_args.py`（`prepare_server_args()` / `PortArgs`）。

| 字段 | 典型 CLI | 作用 |
|---|---|---|

| `tp_size` | `--tp` / `--tp-size` | Tensor parallel |
| `pp_size` / `dp_size` / `ep_size` | `--pp` / `--dp` / `--ep` | 流水线 / 数据 / 专家并行 |
| `nnodes` / `node_rank` / `dist_init_addr` | 同名 | 多机 |
| `mem_fraction_static` | `--mem-fraction-static` | 静态权重+KV 占显存比例 |
| `attention_backend` | `--attention-backend` | flashinfer / triton / fa3… |
| `quantization` | `--quantization` | 量化方法 |
| `speculative_algorithm` | `--speculative-algorithm` | EAGLE / EAGLE3 / MTP… |
| `enable_lora` / `lora_paths` | `--enable-lora` | Multi-LoRA |
| `disaggregation_mode` | `--disaggregation-mode` | `null` / `prefill` / `decode` |
| `chunked_prefill_size` | `--chunked-prefill-size` | Chunked prefill |
| `max_running_requests` | `--max-running-requests` | 并发上限 |

完整列表：[Server Arguments](/docs/advanced_features/server_arguments)、[Environment Variables](/docs/references/environment_variables)。

### 3.4 常用部署配方

**单机多卡 TP：**

```bash
sglang serve --model-path MODEL --tp 8 --host 0.0.0.0 --port 30000
```

**多机（每节点一条，改 `--node-rank`）：**

```bash
python3 -m sglang.launch_server --model-path MODEL --tp 16 \
  --dist-init-addr 172.16.4.52:20000 --nnodes 2 --node-rank 0
```

文档：[Multi-node](/docs/references/multi_node_deployment/multi_node)。

**Docker：**

```bash
docker run --gpus all --shm-size 32g -p 30000:30000 --ipc=host \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  --env "HF_TOKEN=<secret>" \
  lmsysorg/sglang:latest \
  python3 -m sglang.launch_server --model-path MODEL --host 0.0.0.0 --port 30000
```

**PD 分离：** Prefill / Decode 各起一组进程，`--disaggregation-mode prefill|decode`，前端用 `sgl-model-gateway` 路由。见 [PD Disaggregation](/docs/advanced_features/pd_disaggregation)。

**验活：**

```bash
curl http://127.0.0.1:30000/v1/models
curl http://127.0.0.1:30000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"default","messages":[{"role":"user","content":"你好"}],"max_tokens":64}'
```

### 3.5 部署排障清单

1. `CUDA_HOME` 未设置 → FlashInfer / 编译失败。
2. `--shm-size` / `--ipc=host` 不够 → NCCL 或 tokenizer 共享内存问题。
3. 多机 `dist_init_addr` 防火墙 / 端口不一致。
4. OOM：调低 `mem_fraction_static`、减小 `max_running_requests`、开 chunked prefill。
5. 子进程挂了主进程还活着：看 scheduler 日志；`killall_sglang` 清残留。

## 4. 进程架构（部署与读码的共同基础）

`Engine._launch_subprocesses`（`srt/entrypoints/engine.py`）装配整机：

| 角色 | 进程 | 职责 |
|---|---|---|
| Tokenizer + HTTP | **主进程**（`node_rank==0`） | FastAPI、`TokenizerManager`、可选 TemplateManager |
| Scheduler | **每 GPU rank 一子进程** | 收请求、组 batch、跑 `ModelRunner` |
| Detokenizer | **独立子进程**（可多 worker + router） | token → 文本，回传主进程 |
| 非 0 节点 | 仅 Scheduler（+ dummy health） | 不跑 tokenizer/HTTP |

IPC 端口在 `PortArgs`：`tokenizer_ipc_name`、`scheduler_input_ipc_name`、`detokenizer_ipc_name`（本机多为 `ipc://`，跨机/DP 可为 TCP）。

消息类型集中在 `srt/managers/io_struct.py`（如 `GenerateReqInput`）。改协议时先改这里，再改收发两端。

### RuntimeContext：配置怎么读

进程单例：`srt/runtime_context.py` → `get_context()`。

| 层级 | 访问器 | 含义 |
|---|---|---|
| 原始种子 | `get_server_args()` | 启动时 pristine `ServerArgs`（调试 / dump） |
| 决议配置 | `get_exec()` / `get_memory()` / `get_schedule()` … | **业务逻辑应读这里** |
| 运行时 flags | `get_flags()` | 非纯配置状态（cuda graph、MoE backend…） |
| 资源 | `get_resources()` / `get_stream()` / `get_buffer()` | graph pool、side stream… |
| 单次 forward | `get_forward()` | contextvar，forward 作用域 |

约定（详见 `.claude/skills/sglang-runtime-context/SKILL.md`）：

- **不要**在业务代码里到处 `os.getenv("SGLANG_...")`；新环境变量进 `srt/environ.py` 的 `Envs`。
- 发布后改配置：**唯一入口** `get_context().override(...)`；不要写回 `ServerArgs`。
- Tokenizer / entrypoints 边界可继续读 `self.server_args`（多 Engine 同进程场景）。

## 5. 请求全链路精读

按下面顺序打开文件，对照一次真实请求。

### 5.1 HTTP 入口

- `srt/entrypoints/http_server.py`：`launch_server()`、`/generate`、挂载 OpenAI 路由
- `srt/entrypoints/openai/serving_chat.py`：`OpenAIServingChat`
- `srt/entrypoints/openai/serving_base.py`：`handle_request`

OpenAI 路径把 HTTP body 转成 `GenerateReqInput`，再进入 `TokenizerManager`。

### 5.2 TokenizerManager（主进程）

文件：`srt/managers/tokenizer_manager.py`

重点方法：

1. `generate_request` — 异步入口，管理 rid、流式 future
2. `_tokenize_one_request` — 文本/多模态 → input ids
3. `_send_one_request` — ZMQ 发往 Scheduler

读码时关注：abort、LoRA adapter 热加载、metrics、与 detokenizer 回包的配对。

### 5.3 Scheduler（GPU 子进程）

文件：`srt/managers/scheduler.py`（大类；改动前读 `.claude/skills/large-class-style/SKILL.md`）

主循环两种：

- `event_loop_normal`：收请求 → `get_next_batch_to_run` → `run_batch` → `process_batch_result`
- `event_loop_overlap`：CPU 后处理与下一拍 GPU forward 重叠（默认高性能路径）

配套：

| 文件 | 作用 |
|---|---|
| `scheduler_components/request_receiver.py` | ZMQ 收包 |
| `schedule_batch.py` / `schedule_policy.py` | batch 结构与调度策略 |
| `tp_worker.py` | `TpModelWorker.forward_batch_generation` |
| `detokenizer_manager.py` | 解码侧 |

`run_batch` 是「调度世界」到「模型世界」的桥：准备 `ForwardBatch`，调用 worker，处理输出 token / finished 标志，再决定写回 cache、发 detokenize。

### 5.4 ModelRunner 与模型

- `srt/model_executor/model_runner.py`：`ModelRunner.forward` / `_forward_raw`、attention backend 初始化、cuda graph
- `srt/model_executor/forward_batch_info.py`：`ForwardBatch`
- `srt/models/llama.py`：典型因果 LM（`RadixAttention` + `LogitsProcessor` + `EntryClass`）
- `srt/models/registry.py`：扫描各模块 `EntryClass` → `ModelRegistry`

### 5.5 RadixAttention / KV Cache

- `srt/layers/radix_attention.py`：层侧 attention 接口
- `srt/mem_cache/radix_cache.py`：前缀树缓存（`Scheduler.tree_cache`）
- `srt/mem_cache/registry.py`：cache backend 注册（`--radix-cache-backend`）
- allocator / HiCache / 外部存储：`mem_cache/allocator/`、`mem_cache/storage/`

RadixCache 回答两个问题：这段前缀是否已在 GPU KV 里？没有的话从哪分配 page？读懂它，才能改 chunked prefill、PD KV 传输、多租户缓存策略。

## 6. 开发工作流

### 6.1 日常循环

1. 源码 editable 安装 + `pre-commit install`
2. 开 feature 分支（不要直接推 `main`）
3. 改代码 → 本地最小复现（单测或 `bench_one_batch`）
4. `pre-commit run --all-files`
5. 按 [Contribution Guide](/docs/developer_guide/contribution_guide) 开 PR，补测试与准确率/性能说明

### 6.2 加新模型（最高频贡献）

官方步骤：[How to Support New Models](/docs/supported-models/support_new_models)。

精简 checklist：

1. 在 `python/sglang/srt/models/` 新增文件（常从 `llama.py` / 相近架构复制）。
2. 用 SGLang 层：`RadixAttention`、`LogitsProcessor`、`RMSNorm` 等；`forward(..., forward_batch)`。
3. 文件末尾：`EntryClass = MyForCausalLM`（或 list）。
4. VLM 额外：`model_config.is_multimodal_model`、`multimodal/processors/`、`pad_input_ids`、`get_image_feature`。
5. 调试对比：
   - `python3 scripts/playground/reference_hf.py --model-path MODEL`
   - `python3 -m sglang.bench_one_batch --correct --model MODEL`
6. 注册测试：`test/registered/models/test_generation_models.py` 的 `ALL_OTHER_MODELS`；本地：
   ```bash
   ONLY_RUN=Org/Model python3 -m unittest test_generation_models.TestGenerationModels.test_others
   ```

外部包可不改源码：

```python
from sglang.srt.models.registry import ModelRegistry
ModelRegistry.models[arch_name] = MyClass
```

### 6.3 写测试

| 类型 | 位置 | 说明 |
|---|---|---|
| 无 GPU 单测 | `test/registered/unit/` | 镜像 `srt/` 目录结构 |
| CI e2e | `test/registered/<area>/` | 模块级 `register_cuda_ci(...)` |
| 本地特殊 | `test/manual/` | 不进默认 CI |
| JIT kernel | `test/registered/jit/` | 与 kernel 源码分离 |

跑法：

```bash
pytest test/registered/unit/mem_cache/ -v
python3 test/registered/core/test_srt_endpoint.py
python3 test/run_suite.py --hw cuda --suite base-b-test-1-gpu-small
```

原则：能 CPU 单测就别拉整服务器；e2e 用最轻 suite（见 `test/README.md`、`.claude/skills/write-sglang-test/SKILL.md`）。

### 6.4 改三大类时的风格

`Scheduler`、`TokenizerManager`、`ModelRunner` 有冻结式约定：

- `__init__` 做编排，细节下沉 mixin / helper / `scheduler_components/`
- 避免在大类里继续堆几百行业务分支
- `ModelRunner` 对「再加状态」更敏感——优先查 skill 与现有属性生命周期

见 `.claude/skills/large-class-style/SKILL.md`。

### 6.5 环境变量

新 `SGLANG_*`：

1. 在 `srt/environ.py` 声明（`EnvBool` / `EnvInt` / …）
2. 文档补 `docs_new/docs/references/environment_variables.mdx`
3. 禁止散落 `os.getenv("SGLANG_...")`

见 `.claude/skills/env-var-conventions/SKILL.md`。

## 9. 最小开发练习（建议按序做）

1. **部署**：本机或 Docker 起 `0.5B～8B` 模型，打通 OpenAI chat。
2. **读码**：在 `TokenizerManager.generate_request` 与 `Scheduler.run_batch` 各打一行结构化日志，确认 rid 贯通。
3. **模型**：fork 一个极简模型文件改名注册（或 external registry），跑 `bench_one_batch --correct`。
4. **测试**：为你改的纯逻辑加 unit test，并 `register_cuda_ci` 或只进 unit suite。
5. **性能**：对同一模型跑 `bench_serving`，学会看 TTFT / TPOT / 吞吐；再用 [profiling 文档](/docs/developer_guide/benchmark_and_profiling) 抓一条 trace。

## 10. 常见坑

| 坑 | 正确做法 |
|---|---|
| 在业务里读 `os.environ["SGLANG_…"]` | 走 `envs.XXX.get()` |
| 改完 `ServerArgs` 却在别处直接改字段期望全局生效 | `get_context().override` + namespace bags |
| 在 `Scheduler`/`ModelRunner` 里继续堆巨型方法 | 抽 mixin/component，遵守 large-class skill |
| 只改模型文件不测 HF 对齐 | `reference_hf` + `bench_one_batch --correct` |
| e2e 测试放错 suite / 忘记 `register_*_ci` | 对照 `test/README.md` |
| 多机只改 `tp` 不改 `nnodes`/`node_rank` | 每节点完整一组分布式参数 |
| PD 模式当单机参数乱配 | 明确 prefill/decode 角色 + gateway |

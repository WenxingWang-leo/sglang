# 10 · 开发、调试与贡献指南

> 本篇汇总日常开发所需:环境搭建、代码规范、测试体系、调试工具箱,
> 以及向社区提 PR 的完整流程。无论你改主仓还是做设备适配,都以本篇为操作手册。

---

## 1. 开发环境搭建

### 1.1 源码安装(开发模式)

```bash
git clone https://github.com/sgl-project/sglang.git
cd sglang
pip install -e "python[dev]"        # 可编辑安装 + 开发依赖
```

> 需要内核改动时另装/编译 `sgl-kernel`;做 JIT 内核开发参考
> `.claude/skills/add-jit-kernel/SKILL.md` 与官方 `development_jit_kernel_guide.mdx`。

### 1.2 pre-commit(必装)

```bash
pip install pre-commit
pre-commit install
pre-commit run --all-files        # 首次全量跑一遍
```

钩子链(`.pre-commit-config.yaml`):**isort → ruff → black → codespell → clang-format(C++/CUDA)**,外加尾随空格、中文字符检查、CI 注册校验等本地钩子。提交前会自动运行;CI 也会复查,所以本地先跑通。

## 2. 测试体系(`test/README.md` 为纲)

### 2.1 CI 三段式

```
Stage A(pre-flight,约 3 分钟)→ Stage B(basic,约 30 分钟)→ Stage C(advanced,约 30 分钟)
```

kernel 与多模态生成测试与 Stage B 并行。快速失败、按资源分片。

### 2.2 目录约定

- `test/registered/`:**所有 CI 测试**,按类别分子目录(`core/unit/models/sampling/attention/mla/lora/quant/hicache/radix_cache/disaggregation/spec/dp_attn/ep/pp/cpu/amd/npu/xpu/musa/...`),自动发现;
- `test/manual/`:不进 CI 的测试;
- `test/run_suite.py`:套件运行器。

### 2.3 本地运行

```bash
# 单文件 / 单方法
python3 test/registered/core/test_srt_endpoint.py
python3 test/registered/core/test_srt_endpoint.py -k test_method_name

# 跑套件
python3 test/run_suite.py --hw cuda --suite base-b-test-1-gpu-small
python3 test/run_suite.py --suite nightly-1-gpu --nightly
```

常用套件:`base-a-test-cpu`(无 GPU)、`base-b-test-1-gpu-small`(默认,32GB 卡可跑)、`base-b-test-1-gpu-large`(Hopper/大显存)、`base-c-test-*`(多卡)、`nightly-*`。

### 2.4 CI 注册(硬性要求)

每个 CI 测试文件**必须**在模块级注册,且参数为字面量(CI 用 AST 解析):

```python
from sglang.test.ci.ci_register import register_cuda_ci

register_cuda_ci(est_time=80, stage="base-b", runner_config="1-gpu-small")
```

文件末尾以 `unittest.main()` 或 `pytest.main([__file__])` 收尾。写测试时参考
`.claude/skills/write-sglang-test/SKILL.md`(fixture、模型选择、服务器复用等模板)。

### 2.5 测试工具(`python/sglang/test/`)

- `launch_server` / `popen_launch_server`:拉起真实服务器做 e2e;
- `few_shot_gsm8k.py`:快速精度冒烟;
- 建议 `setUpClass` 复用服务器,单文件控制在 500s 内。

## 3. 调试工具箱

### 3.1 日志与环境变量

- `--log-level debug`、`SGLANG_LOG_*` 系列:调度与请求轨迹;
- `--log-requests`:记录每个请求的调度细节;
- `SGLANG_IS_IN_CI=1` 等 CI 行为开关。
- 环境变量集中定义在 `srt/environ.py`(新增变量遵循 `env-var-conventions` skill:在哪里定义、如何命名、如何废弃)。

### 3.2 性能剖析

- 官方 profile 流程:`.claude/skills/generate-profile/SKILL.md`(起服务器 → 验证精度 → 抓 Chrome trace);
- torch profiler:`SGLANG_TORCH_PROFILER_DIR` + `/start_profile`、`/stop_profile` HTTP 端点;
- 分析:`llm-torch-profiler-analysis` skill 可把 `trace.json` 变成 kernel/overlap/fuse 三张表。

### 3.3 分布式挂死

多卡 hang 是适配期常客。方法论(`debug-distributed-hang` skill):

1. `py-spy dump` 每个 rank 的调用栈,定位卡在哪个集合通信;
2. 对比各 rank 日志找**状态分叉点**(拼批决策不一致 = 死锁);
3. 用 `SGLANG_TORCH_DISTRIBUTED_DEBUG` / watchdog 超时信息缩小范围;
4. 二分定位首个分叉 commit/决策。

### 3.4 CUDA 崩溃

`debug-cuda-crash` skill:用 kernel API logging 记录每次 kernel 调用参数,复现并定位非法访存。

### 3.5 线上问题分诊

`sglang-prod-incident-triage` skill:replay-first 流程,把线上症状(超时/吞吐退化/输出错误)转化为可复现 replay,再选工具。

### 3.6 运行时上下文

改 `server_args`、模块级全局状态、per-forward 状态前,读 `sglang-runtime-context` skill——SGLang 对「配置分层 + 无状态前向」有 CI 强制约束,乱加全局变量会挂 CI。

## 4. 贡献流程(PR)

1. **Fork + 分支**:不要直接向 `main` 提交;
2. 改动 + 测试(新功能必须带测试;CI 注册按 §2.4);
3. `pre-commit run --all-files` 通过;
4. 文档链接检查:CI 用 lychee 校验,本地可跑
   `pre-commit run --hook-stage manual lychee --all-files`;
5. 提交 PR,描述清楚动机、测试方式、性能影响(有数据最好);
6. 大改动先在 issue/discussion 对齐设计。

官方贡献文档:`docs_new/docs/developer_guide/contribution_guide.mdx`(及同目录的 docker 开发、量化贡献、模型评估等指南)。

## 6. 给「设备适配者」的开发建议

1. **先 fork、后插件**:主仓改动越少,长期维护成本越低。能走 entry-point 插件的绝不改主仓。
2. **CI 先行**:尽早把你的设备测试放进 `test/registered/<device>/`,用最小模型冒烟。
3. **对照树内实现**:NPU/XPU/MUSA 的目录结构就是你的模板(attention/graph_runner/moe/quantization)。
4. **数值基准**:固定 seed,与 `torch_native` + CUDA 参考输出逐 token 比对,再谈性能。
5. **记录差异**:维护一份「与主仓行为差异清单」,rebase 时按清单回归。

## 7. 本篇要点回顾

1. 开发 = 源码可编辑安装 + pre-commit(isort/ruff/black/clang-format)。
2. CI 三段式;测试必须注册(`register_cuda_ci`,字面量参数),放 `test/registered/`。
3. 调试:日志/env → torch profiler → py-spy 分栈 → 专用 skill(挂死/崩溃/线上)。
4. PR 流程:分支开发、带测试、过 pre-commit 与 lychee。
5. 设备适配者:插件优先、CI 先行、对照树内实现、数值基准固定。

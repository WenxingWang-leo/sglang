# 09 · 分布式推理:TP / PP / DP attention / EP

> 本篇解析 SGLang 的并行体系:通信组如何建立、TP 如何切层、DP attention 如何省显存、
> MoE 的 EP 如何 all-to-all、PP 如何接力。多卡适配(第三方设备的常见诉求)必读。

---

## 1. 并行维度速查

| 维度 | 参数 | 切什么 | 通信 | 典型用途 |
|---|---|---|---|---|
| TP | `--tp-size` | 层内权重(列/行切) | 每 block 2 次 all-reduce | 单模型放不进单卡 |
| PP | `--pp-size` | 层间(前 N 层/后 N 层) | 相邻 stage send/recv | 超大模型跨节点 |
| DP attention | `--dp-size` + `--enable-dp-attention` | 请求/token 划分 attention | attn 本地,MoE 前 gather | 大 batch 吞吐 |
| EP | `--ep-size` | MoE 专家分布 | all-to-all(DeepEP 等) | 大 MoE 模型 |
| CP/DCP | context parallel | 序列切分 | 视实现 | 超长上下文(实验) |

SGLang 的 `distributed/` 源自 vLLM(后者源自 Megatron-LM),核心是 `parallel_state.py`。

## 2. 通信组的建立

入口 `initialize_model_parallel(...)`(`distributed/parallel_state.py:2176`),在 `bootstrap.py` 的分布式初始化流程中被调用。它按 `tp_size × pp_size == world_size` 的约束,把全局 rank 划分成:

- `_WORLD`:全局组;
- `_TP`:tensor parallel 组(相邻 rank);
- `_PP`:pipeline parallel 组(跨步长 rank,如 `[0,2,4,6]`);
- 以及 attention/MoE 专用组:`_ATTN_TP`、`_ATTN_CP`、`_DCP`、`_MOE_DP`、`_MOE_EP`、`_MOE_TP`。

经典例子(8 卡,TP=2 × PP=4):TP 组 `[0,1] [2,3] [4,5] [6,7]`;PP 组 `[0,2,4,6] [1,3,5,7]`。

组的运行时访问器:`get_tp_group()`(:1874)、`get_pp_group()`(:1933)、`get_moe_ep_group()` 等,返回 `GroupCoordinator`。

### 2.1 GroupCoordinator:集合通信的瑞士军刀

`parallel_state.py:221`。一个组一个实例,提供:

- 张量集合:`all_reduce`、`all_gather`、`gather`、`broadcast_tensor_dict`;
- 点对点:`send` / `recv` / `send_tensor_dict` / `recv_tensor_dict`;
- 对象:`send_object` / `recv_object`(pickle);
- 图捕获:`graph_capture(stream)` 上下文管理器(CUDA Graph 捕获期间切换通信流);
- 分发到不同底层:**pynccl**(默认)、custom all-reduce(小消息优化)、pymscclpp、torch symm mem、或退化为 torch.distributed。

功能层封装在 `communication_op.py`:`tensor_model_parallel_all_reduce`(最常用)、`tensor_model_parallel_all_gather`、`broadcast_tensor_dict` 等。

> 适配要点:第三方设备的集合通信通常通过 `get_torch_distributed_backend_str()` 指定后端串(如 `"mccl"`),复杂场景实现 `get_communicator_class()` 返回自定义 communicator(参考 `device_communicators/npu_communicator.py`)。

## 3. TP:层内切分如何落地

TP 的语义完全编码在 `layers/linear.py` 的四种 Linear 里:

### 3.1 ColumnParallelLinear(按输出维切)

`Y = X·A + b`,`A = [A_1 … A_p]` 沿输出维切到 p 个 rank。每 rank 持有 `output_size_per_partition = output_size / tp_size` 列,`gather_output=False` 时输出保持本地分片(与后续 Row 层衔接)。

### 3.2 RowParallelLinear(按输入维切)

输入已是分片,权重沿输入维切;`reduce_results=True` 时对输出做 all-reduce。

### 3.3 经典配对:每 block 两次 all-reduce

```
attention:  QKVParallelLinear(列切) → … → o_proj = RowParallelLinear(行切 + all-reduce)
MLP:        gate_up = MergedColumnParallelLinear(列切) → down_proj = RowParallelLinear(行切 + all-reduce)
```

### 3.4 QKVParallelLinear:按头切,GQA 时复制 KV

头数能整除 tp_size 时按头均分;`tp_size > num_kv_heads`(GQA/MQA)时 **KV 头被复制**到多个 rank(`num_kv_heads=1` + replicas),保证每 rank 都有完整 KV 可用。

### 3.5 权重加载配合

`load_weights` 里的 `weight_loader` 按 shard_id 与 TP rank 只写入自己那份切片(见文档 05)。**TP 正确性 = 切分公式与 weight_loader 的一致性**,排查 TP 数值错误时优先核对这两处。

## 4. DP attention:注意力分数据,MoE 聚合

`layers/dp_attention.py` + `managers/data_parallel_controller.py`。

动机:大 batch decode 时,attention 部分计算量不大但 KV 显存吃紧。DP attention 让每个 DP worker 只处理**一部分请求的 attention**(各持自己的 KV 分片),进入 MLP/MoE/lm_head 前再 **all-gather 拼回全量 token**,算完再 scatter 回去。

关键设施:

- `compute_dp_attention_world_info()`:由 `tp_size / dp_size / attn_cp_size` 推出 `attn_tp_size` 与 rank 布局 `(dp, cp, tp)`;
- 集合:`dp_gather_partial` / `dp_gather_replicate` / `dp_scatter` / `dp_reduce_scatter_tensor`,以及 FP8 gather、TBO 异步变体;
- 缓冲:`_DpGatheredBufferWrapper` 管理全局/本地 DP buffer(`set_dp_buffer_len`);
- padding 模式:`DpPaddingMode.MAX_LEN`(pad 到最大长 + all_gather)vs `SUM_LEN`(pad 到总和 + all_reduce)。

请求分发由 **DataParallelController**(`managers/data_parallel_controller.py:131`)负责,策略(`LoadBalanceMethod`):`ROUND_ROBIN`、`FOLLOW_BOOTSTRAP_ROOM`、`TOTAL_REQUESTS`、`TOTAL_TOKENS`,基于各 DP worker 的 shm 负载快照做决策。每个 DP worker 内部仍是一组 TP scheduler(`tp_size*pp_size` 个进程)。

调度侧配套:`ForwardMode.IDLE` 处理某 rank 无 token 的情况;overlap 决策需跨 DP rank 同步(避免集合通信死锁)。

## 5. EP:MoE 专家并行

`layers/moe/`。两条路线:

### 5.1 TP 式 MoE(`FusedMoE`)

专家在每 rank **复制**,但每个专家的权重按 TP 切分(类似 Column+Row)。适合专家数多、单专家小的场景,无 all-to-all。

### 5.2 EP 式 MoE(`DeepEPMoE` + token dispatcher)

专家**分布**到不同 rank,token 需要 all-to-all 路由:

```
hidden → topk 路由 → dispatcher.dispatch(all-to-all 发 token 到专家所在 rank)
      → 本地 grouped GEMM(专家计算)
      → dispatcher.combine(all-to-all 回传 + 加权求和)
```

dispatcher 抽象在 `token_dispatcher/`:

- `base.py`:`BaseDispatcher` / `DispatchOutput` / `CombineInput`;
- `deepep.py`:`DeepEPDispatcher`——**normal 模式**(prefill,大吞吐)与 **low-latency 模式**(decode,CUDA Graph 友好)两套路径;
- 其它:`pplx`、`flashinfer`、`mooncake`、`moriep`、`nixl`、`standard`、`ascend_tp` 等。

EP 组由 `initialize_model_parallel(expert_model_parallel_size=…)` 建立的 `_MOE_EP` 承载;MoE 层内部还可叠加 MoE TP(`_MOE_TP`)与 MoE DP(`_MOE_DP`),即社区常说的 DP+EP 组合。

> 适配提示:EP 的性能核心是 all-to-all。第三方设备先跑通 TP 式 `FusedMoE`(无 a2a),再移植 dispatcher。

## 6. PP:层间接力

- `utils/common.py` 的 `make_layers(num_layers, layer_fn, pp_rank, pp_size, …)` 调 `get_pp_indices()`(`distributed/utils.py:95`)算出本 rank 的 `[start_layer, end_layer)`,只实例化这一段,其余用 `PPMissingLayer` 占位;多余层分给**最后**几个分区;可用 `SGLANG_PP_LAYER_PARTITION` 手工指定。
- 运行时:`managers/scheduler_pp_mixin.py` 在调度循环中实现 stage 间的 send/recv(中间激活 + 采样信息流转)。
- 权衡:PP 通信量小(只有激活),但气泡(bubble)天然存在;SGLang 主战场是 TP + DP attention,PP 更多用于超大模型。

---

## 7. 多机组网

- `--nnodes` / `--node-rank` / `--dist-init-addr`:多节点启动;`node_rank >= 1` 的节点只跑 scheduler 进程。
- 通信后端按平台选择(NCCL/RCCL/xccl/hccl/…),RDMA 由底层集合库负责。
- TP rank0 广播调度决策的机制在多节点同样成立(走 NCCL broadcast)。

---

## 8. 本篇要点回顾

1. `initialize_model_parallel` 建立 TP/PP/attention/MoE 全套组;`GroupCoordinator` 是统一操作面,底层可切 pynccl/custom/自研。
2. TP = ColumnParallel + RowParallel 配对,每 block 两次 all-reduce;GQA 时 KV 头复制。
3. DP attention = attention 分数据 + MoE 前 gather;由 DataParallelController 按负载分发请求。
4. EP = dispatcher 驱动的 all-to-all;DeepEP 有 normal/low-latency 双模式。
5. 第三方设备适配顺序建议:单卡 → TP(通信后端)→ DP attention → EP。
